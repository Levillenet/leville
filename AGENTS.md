# Project conventions
- Privileged browser-callable edge functions use the shared authGuard CORS and credential helpers so admin session headers stay consistent.
- Restaurant guide additions belong in the existing bilingual restaurant-guide data and use optimized WebP CDN asset pointers, because both language pages share the same gallery and raw camera images should not be served.

- Startup path must not statically import the backend client, recharts or framer-motion; use `getSupabase()` (src/lib/getSupabase.ts) in code that runs on public pages, because these chunks were hurting mobile LCP.
- Shared layout components are grouped into a `layout` chunk in vite.config.ts manualChunks; keep new always-used layout components there.
- Build runs scripts/generate-route-preloads.mjs after vite build to write per-route HTML with page-chunk modulepreloads; `#root` stays empty in those files because static shells caused CLS regressions.
- Toasters are mounted via DeferredToasters (idle) and `Tooltip` wraps its own provider, so neither belongs in the startup bundle.
- The catch-all route (SeoCatchAll) must render a neutral shell, never NotFound, until the seo_pages lookup has resolved, so crawlers never snapshot a transient 404; unmatched URLs start the lookup immediately, matched ones at idle.
- Property hero images in public/ have pre-generated `-480w`/`-800w` WebP siblings used via srcset in PropertyCard; regenerate them when a heroImage changes, so mobile cards stay under ~60 kB.
- Above-the-fold text on landing pages is not wrapped in ScrollReveal, because its opacity-0 start delayed LCP.
- Staff operational redirects bypass visitor layout, tracking and path normalization; keep them out of sitemap discovery because they are external workflow links, not public content.
- All Moder outbound navigation uses appendAdParams through the startup-installed link handler (including dynamic anchors, window.open and embed searches), so campaign attribution has one implementation independent of analytics.
- Consent Mode defaults must be the first HTML script; the shared cookieConsent module gates statistics and advertising independently and preserves versioned choice evidence, so withdrawal stops reporting and propagation immediately.
- GoogleAnalyticsTracker owns the single consent-gated GA4 installation, SPA page views and delegated booking/email click events; the initial config owns only the first page view to avoid duplicate app-generated reports.
- Dated Moder searches go through trackSearchThenNavigate (one event per search, deduped across handlers; navigation on event_callback or 150 ms), so link and embed-search paths never double-count.
- Consented widget navigation dispatches mousedown on an attached data-lv-nav anchor before clicking its decorated href; both delegated Moder handlers skip this marker to preserve linker decoration without repeating tracking or delays.
- Short social tags (?fb=/?ig=) are expanded to UTM parameters by src/lib/shortCampaign.ts, imported first in main.tsx, so every analytics and link-decoration path sees only standard UTMs.
- The empty-search rescue (src/lib/emptySearch.ts + check-availability function) may stop Moder navigation only when the pre-check returned exactly 0; pending (>1000 ms), null, errors or unreadable widget state always navigate as before, so search can never break. The pre-check and find-alternatives always query exact dates and share supabase/functions/_shared/moderResult.ts, so "free" means the same everywhere and flexible-only results never count.
- Search-bar analytics are /event/haku* rows in page_views logged via src/lib/searchLog.ts regardless of consent (memory-only ids, no IP/UA/country); aggregation lives in src/lib/searchDemand.ts so the admin views stay testable.
- Moder HTML stay totals are extracted only from the marked Rates section by the shared moderResult parser, because arbitrary euro text can be an add-on fee; ambiguous totals return null.
